# 从用户原图匹配参考

本步骤的产物是内部选图依据，不向用户追加多张方案。原图理解与最终视觉复排由宿主模型看图完成；Python只对结构化条件排序，不识图、不理解文意，也不宣称相似度。

选图还须读取[核心创意规则](creative-reading.md)。每张参考的具体优点与创意简卡随检索返回，选定候选再用 `scripts/creative.py --id` 读完整档案。**核心创意能否由本次内容成立，优先于版式兼容分**。以[创意对照表](creative-atlas.md)或 `scripts/creative.py --mechanism cross_plane` 可比较同一机制的不同实现，不能凭机制同名互相替代。

## 1. 看原图，形成内容档案

先实际打开用户图，再翻译并确定最终标题。识别真正需要使用的内容区域，排除手机状态栏、截图裁剪按钮、黑边、桌面任务栏等无关区域；不能仅按整张手机截图的长宽比选模板。仍需保留说明主题所需的真实界面状态。

在内部工作目录写 `source-profile.json`，最小示例：

```json
{
  "source_type": "interface",
  "image_size": [1320, 2868],
  "effective_region": [0.12, 0.35, 0.94, 0.59],
  "title": "Higher settings. More headaches.",
  "preserve_fields": ["the actual model name", "the visible reasoning setting and slider state"],
  "allow_crop": true,
  "allow_cutout": false,
  "allow_duotone": true,
  "preserve_colors": false,
  "auxiliary_text": "low",
  "intent": "Higher reasoning settings may create more trouble, not an endorsement of maximum settings."
}
```

这是格式示例，**坐标和字段不是任何输入的通用默认值**。必须对照本次实际像素重填，模型名和状态尽量抄录实际可读值，不能凭示例猜测。`effective_region` 是原图内归一化的 `[左,上,右,下]` 有效区域；覆盖所有必要主体与真实字段，而非为了迎合参考随意缩小。后续生成仍使用原始内容图并说明这个区域。

| 字段 | 含义 |
| --- | --- |
| `source_type` | 必填：portrait / object / food / scene / interface / document / mixed / unknown。按画面实质而非拍摄设备分类 |
| `image_size` | 必填：原文件真实像素 `[宽,高]`，正整数 |
| `effective_region` | 有效内容边界，默认整图并产生复查提醒。主体多个不相连时，取能保全必要内容的范围，并在 `photo_note` 说明 |
| `title` | 必填：本次最终主文案，通常为英文；不能用待翻译中文的长度替代最终排字长度。字数容量是粗略提示，须看字形、字符宽度和实际断行 |
| `preserve_fields` | 必须可读的真实文字/数值字段及其状态关系，字符串列表。存在此项将提高完整图像和文字可读性的优先级。**只放文字字段，不把普通主体轮廓和颜色填进这里** |
| `preserve_features` | 必须保留的视觉身份、物体形状、纹理、颜色和位置关系，字符串列表；普通食物/物体用本项，不因此误当成文字截图。关键颜色另用preserve_colors保护 |
| `allow_crop` / `allow_cutout` | 是否可裁切有效内容、抠图或蒙版，默认true；界面可裁无关背景，但不能丢失受保护字段。不可抠图时填false |
| `allow_duotone` / `preserve_colors` | 默认true / false。依照本次内容能否去色和是否需要原色填写；与用户明确要求一致 |
| `auxiliary_text` | low / medium / high，默认low。表示能忠于原意组织的辅助文案预算；high不是允许编造事实，也不由源图文字多少自动决定 |
| `palette` / `energy` | 可选审美偏好。palette用索引内的标准色词；energy为restrained / neutral / dynamic / solemn / playful。不因输入有蓝色UI就自动要求蓝色模板 |
| `intent` / `photo_note` | 可选：语义、主要形状、留白、不可改变的关系及图片局限。脚本不对其做关键词语义匹配，最终复排必须读它们 |

默认只让用户提供一张图与文案，这份档案由执行者填写，不变成用户问卷。只在确实缺关键信息时提问。没有本地路径的附件仍可看图后建档；无需上传到外部检索服务。

## 2. 全库排序，生成候选

从Skill根目录执行（其他工作目录用脚本绝对路径）：

```text
python -X utf8 scripts/library.py --profile /absolute/path/source-profile.json --limit 12
python -X utf8 scripts/library.py --profile /absolute/path/source-profile.json --reference 151
```

第一条对全部170项计算：主体如何进入版面、有效区域长宽比、最终标题容量、辅助文案预算、改幅与图像处理代价。保护界面文字比装饰配色重要。第二条只用于用户明确指定编号，保留其选择并说明适配风险，不替用户换参考。

Windows含中文输出使用上面的 `-X utf8`；如需保存JSON，优先由Python以UTF-8写文件，避免旧PowerShell管道按本机编码重解码。脚本运行不了时，直接读取同一视觉档案筛查全库，再看联系表及候选单图完成比较，记录“手工档案筛查”；不编造脚本分数，也不把填写档案或安装依赖转嫁为用户必须操作的步骤。

`compatibility_utility` 是可解释的兼容性启发分，**不是视觉相似度、置信度或概率**。`components`、`reasons`、`risks` 一并返回；适度题材/版式家族去重仅改变候选顺序，其惩罚单列。旧 `recommended_start`、编号先后、历史被选次数都不参与该排序。照片原色或不可裁切等限制会降低冲突方案，不伪称硬条件已满足；`permitted_route=false` 表示档案建议的插图方式违反限制，不能直接用于生成。用户指定的参考也须找到允许的替代落点。

索引与实际图片SHA-256绑定；更改后的图片不会继续使用旧档案参与排序，输出 `stale_excluded_ids`。发现非空时先复看对应图片、更新档案和哈希再进行完整检索；不能悄悄忽略缺失部分并宣称完整全库比较。

## 3. 打开实图复排，确定真正适配的那一张

自动模式通常打开排名中至少三张**不同构图且有现实适配可能**的完整图片，与原始输入一起比较；这三张只是内部检查，不是交付三方案。排序首位不能自动等于最终选择。候选仍不合适时扩大 `--limit` 并查对应联系表；有明显更合适者可越过分数顺序，记录实际视觉依据。

每个候选先记录：具体优点、核心创意、必要关系、本次如何实现，以及 `supported/adaptable/unsupported/uncertain` 判断。没有明确的实现关系，不能进入生成。检索初始 `creative_transfer_status=not_reviewed`、`generation_ready=false` 表示尚待实际看图；执行者看完后把结论及依据写入内部任务卡，不可无依据置为通过。`auto_generation_eligible=false` 的批评/反例页不作为自动封面模板。

每张候选给出简短的内部对照：

- 原图的具体哪个部分，放到参考的哪个区域，以什么尺度、处理方式与其他图形接触；身份与受保护字段怎样留下。
- 本次标题怎样断行、采用哪种字形节奏，能否在保留比例与留白的前提下排下。
- 参考实际出现的细字、数字、色带、表格与标记怎样用本次内容承担；不能用“之后再补”掩盖辅助信息不足。
- 本次主旨与画面氛围是否一致，有没有无意引入原海报人物、政治/品牌含义；比较整体明暗、主色面积和视觉冲突，不仅是题材标签相近。
- 改成3:4会损失什么，是否比其他候选需要更大改动。保留色彩、裁切等用户限制能否满足。

`matching-index.json` 的 `observed` 是从联系表可见的粗观察，`adaptation` 是对“如何加入新照片”的推断，**不表示原图天然有这个照片框**。`review.basis=contact_sheet` 不足以确认细字和准确位置；复排须看单图，修正缩略图误读。档案中small/medium/large是等级，不是实测面积；字数带是编辑参考，不是字体像素保证。

### 资料页、标本与纯图形

`kind=collection_page` 表示一页含多个设计，**不能把整页直接当主参考**。打开原图，选定一张具体子海报，记录其归一化子框、为何选它及单独的构图/文字观察；必要时传统裁出子图作为实际图像工具输入，并保留父编号。子图的版式可能与父页概括不同，必须重新检查适配，不直接使用父页的容量和分数。无法可靠分开则换候选。

单张作品中的多阶段序列与资料页不同。例如REF-070的人物填色和字母显影同步发生，序列整体就是核心；不能只裁末格再声称保留了序列创意。档案中的 `subdesigns` 也可能记录阶段或标本分组，最终看 `analysis_unit`、完整图片与该项必保留条件。

`specimen_page` 是字体、技术或内页标本；明确要借的是哪种版式关系，并证明有足够相关内容支撑，不能复制字母表、技术数字或虚构新闻。

纯文字/图形不硬性排除，但需付出可解释的图像融合代价。用户指定时，按入口的字腔、几何面或负空间方案保留用户内容图；自动模式优先能同时满足原图与参考结构的方案。

## 4. 选图结论进入生成任务卡

内部保留源图档案、候选比较、选定编号（资料页另有子框）、实际图像融合位置、关键保护项与已解决风险。将它们连同完整元素映射传入[生成任务卡](generation.md)，再执行图生图和实际成品验收。

在生成任务卡最前面放所选参考的核心创意、具体承接关系、`must_survive`、`generation_anchor` 和 `core_checks`。不能把创意只留在检索JSON中，提示词又退回配色/字体/框线清单。

匹配升级的验证须区分：脚本排序正确、实图复排可执行、最终封面效果。历史被认可的参考是适配实例，不是唯一正确答案；不能把“重新命中REF-006/050/068”当成精确率。未经新实图生成和用户判断，不声称本版提高了最终封面质量的百分比。

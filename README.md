# 阿苏 · 抖音海报封面

**一张图片 + 一段文案 → 一张有海报排版依据的抖音封面。**

`douyin-reference-cover` 是一个 Codex Skill：自动从随包的 **170 张书籍海报参考图**中选一张，将用户图片与该参考一起用于图生图，默认制作全英文封面，并检查文案、整体参考贴近程度和抖音主页裁切。当前版本 **0.5.1**。

## 0.5.1：创意档案复核修正

修正人物数量与方向、握持及连接关系、摄影与绘制媒介、资料页分类和检索标签；来源未明的分色降为可选形式。子图核心现可在对照表直接比较，生成任务卡须承接选定子图的具体关系。此版本已完成档案、检索与本地测试；下方提供一张用户确认的实际封面。单个案例不代表全部170项参考均已通过生图实测。

### 比较每张参考的优点与核心创意

逐张打开170项完整参考后，新增[创意对照表](references/creative-atlas.md)和[完整创意档案](references/creative-index.json)。每项记录具体优点、核心创意、成立关系、改编必要条件、可变内容、常见失败方式、生成锚点和实图验收条件。资料页、序列、字体标本另有210条子图/阶段/分组记录；这些不是210张独立模板。

核心创意能否由本次素材成立，先于版式分。例如REF-112的重点是框内人物与框外纸面虫子的跨层联系；普通截图放进黑框再加一个小物，不能算承接了它。也有参考以身体组成字母、水面对文字产生折射、文字与车轮共形、部件暗示缺席整体等不同方式取胜；字体、材料和信息秩序本身也可以是优点，不强编故事。

检索返回创意简卡，选定前读完整档案；任务卡将具体关系传给图像工具；实际成品先检查关系是否成立，再检查排版和细节。观察、解读及用户反馈依据分开，不冒称已核实作者意图。操作见[创意阅读与承接](references/creative-reading.md)。

```text
python -X utf8 scripts/creative.py --id 112
python -X utf8 scripts/creative.py --mechanism cross_plane
python -X utf8 scripts/creative.py --mechanisms
```

从粗标签浏览升级为“内容建档 → 全库兼容性排序 → 候选实图复排”。用户仍只需提供一张图片和文案。

- 170项视觉档案记录构图、图像类型、信息角色、配色，以及推断的原图融合方式、标题容量和改编代价；观察与推断分开，图片哈希防止档案过期后继续误用。
- 识别源图真正有效区域，按最终英文标题长度、文字字段保护、视觉特征、原色/抠图限制和辅助内容预算检索。普通物体特征不会被误当成截图文字。
- 自动模式比较多个完整候选，明确图像落点和内容承接后才选参考；用户指定编号则保留其选择。资料页先选子图，不把一页多风格拼成模板。
- 分数是结构兼容性的启发值，不是视觉相似度或精确率；语义、氛围、字体节奏仍由实际看图复排判断。

详见[原图匹配流程](references/matching.md)、[170项视觉档案](references/matching-index.json)。本次升级不生成新封面，不替换下方历史实例。

## 使用

将整个仓库放到 Codex 的 `skills/douyin-reference-cover` 目录，保留 `SKILL.md`、`assets`、`references`、`scripts` 和 `agents` 的相对位置。Windows 常用位置为 `%USERPROFILE%/.codex/skills/douyin-reference-cover`。已安装旧版本时先备份，更新这个 Skill 的文件。

提供图片并说：

> 使用 $douyin-reference-cover。标题：吃面条得用筷子，用AI得靠脑子。

Skill 自动选参考，直接制作并只交付一张1080×1440、3:4的JPG封面。过程稿和内部检查图不逐轮展示，不额外提供9:16母版、预览图或格式副本。只要求修订Skill时不生成图片。也可以指定「这次用 REF-021」。无需每次先选风格或填写设计问卷。

封面默认全英文：中文输入忠实翻译，确定的英文逐字使用，允许调整断行和文字层级；用户明确指定其他语言时按指定。参考海报中的品牌、人物和外文不自动带入成品。范围限定为这套参考库驱动的封面制作及修改。

## 独立执行的生产流程

无需历史聊天。入口中的默认语言、单张尺寸、内容边界与工作步骤均可独立使用：

1. 看原图建立有效区域与最终文案档案，对全库排序并打开候选实图复排，选定真正能承接内容的参考。
2. 列出参考的完整元素清单，涵盖细字、编号、色带文字、边框、表格和图形关系。
3. 将每项的内容来源、位置尺度与处理方法写成映射表，确定所有上图文字，逐格列出表格。
4. 将两张实际输入图、整体约束、全部元素与文字清单交给图生图工具。
5. 用实际成品逐项检查整体审美、所有元素与文字；缺失和漂移退回局部修正。
6. 只交付一个通过检查的3:4 JPG。

辅助内容可按原意概括，数值需有依据；参考没有的细节不强加，不能把一个示例的02、黑框或配色套到其他海报。详见 [内容适配](references/content-mapping.md)、[生成任务卡](references/generation.md)与[实图验收](references/reference-fidelity.md)。

## 工具与依赖

生成需要宿主提供可接收参考图片的图像生成/编辑工具，优先使用 Codex 内置图像工具。仅安装 Skill 不会自动提供生图服务；费用随实际宿主工具计费。

检索脚本仅需 Python 标准库，不调用外部检索/嵌入API；裁切检查脚本另需 Pillow：

```text
python scripts/library.py --id 21
python scripts/library.py --tags photographic typography --limit 8
python -X utf8 scripts/library.py --profile /absolute/path/source-profile.json --limit 12
python scripts/check_framing.py cover.png --out-dir framing-check
```

裁切脚本仅检查尺寸、裁切和可选标题框位置，不负责生成图像，也不能证明文字正确或通过平台审核。

匹配行为检查（在可写工作目录执行）可运行 `python -X utf8 -m unittest discover -s /absolute/path/to/skill/scripts/tests -v`。测试不调用生图或网络，迁移测试在当前工作目录创建并清理独立临时副本。
